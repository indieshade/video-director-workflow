# 创作复审、迭代与停止依据

用于完整制作、显著重做，以及用户要求加强主动迭代的项目。草稿、纯讨论、直接重新导出和局部修改沿用其授权范围，不自动重做整片。按 [制作规划](production-planning.md) 发现能力，按本参考决定首版之后做什么。

## 开工时确定观看目标

沿用 [制作规划](production-planning.md#观众最终状态与标志性画面事件) 中的观众最终状态与标志性事件，把最影响本片的观看目标写入现有分镜或风格说明，并预留复审和修订的工作。目标描述观众应该看懂或感到的关系，例如主体怎样受力、群体怎样交接、声音怎样形成段落；不以工具数量、镜头数或统一审美分数定义质量。不为了方便实现主动缩小原 brief，新增创意选择与原始要求分别记录。

## 首版导出之后的下一步

完整作品的首版是内部初稿。技术检查与导出通过后，下一步进入创作复审；创作证据已对应同一个未变化版本时可以复用，不为重复导出制造新的修改轮次。

暂时放下实现过程，从观看者的理解与感受回看成片。检查原始 brief、当前重要目标、能力实际落实和整体推进。用实际片段定位最影响目标的问题，区分技术故障、设计关系不足和未验证内容。不要因为代码投入大就保留一个薄弱选择，也不为了显得挑剔而编造问题。

创作观察写出位置、看到了什么、怎样影响目标和证据。关键帧支持造型、构图与可见状态；实际连续观看支持运动与交接；听取音频支持声音判断；用户反馈只用于它明确覆盖的范围。播放推进、波形与响度只能证明技术状态，无法取得的感官证据保留为未验证。

## 评审者主动取证

从实际交付文件自行选择观察位置，不只看制作方挑选的好看片段或听其完成总结。先看整片推进，再围绕主要转折、标志性事件、可疑切点与衔接取帧；需要判断动作时查看连续片段，过渡附近按问题加密。固定采样间隔和接触表只能辅助定位，不能单独证明运动或节奏通过。

先记下观众实际看到了什么、哪里改变了理解或感受，再与 brief、分镜承诺和可用参考核对。声音关闭时检查对象关系、视觉重点及连续性；声音开启时检查口播匹配、同步、留白与可懂度。未能实际观看或听取的部分继续标为未验证，不以静音复述全部口播作为统一验收条件。

已有独立评审者，或获准使用评审子代理时，交给其原始 brief、必要素材和成片路径，让其自行取证；首次判断前不提供制作方的自评分、预设问题清单或辩解。同提示词比较在条件允许时隐藏作者与模型名称，按完整作品解释主要优点与差距，不用无关小瑕疵抵消整体设计差距。盲测的揭示顺序同样约束评审者。没有独立评审条件时由制作代理明确以自审完成；同模型换一个代理只能减少实现立场的干扰，不能据此声称审美判断更可靠。

评审给出按影响排序的具体问题、时间位置、证据与建议，并说明继续修订或保留的依据；不强制每个镜头启动新代理。修改后既查目标问题，也回查它影响的接缝和已成立的关系，避免修好一处又破坏另一处。

## 由问题驱动修改

选预期收益最高的问题，形成短的设计假设：

`具体问题与证据 → 准备改变的关系 → 希望改善的观看结果 → 局部候选 → 对照判断 → 采用或回退 → 相关接缝与整体复查`

修改可以是删除干扰、替换素材、重新构图、调整动作或声音组织，也可以返回方向设计。不要将加效果、换字体、提高饱和度当成通用迭代。相同关系反复失效时，重新诊断假设或查相关技能与依据，不只累加参数。

保留基线和候选，用适合的比较方式判断收益；不同版本声音比较匹配完整混音响度。同一画面的开关对照定位局部收益，同提示词目标仍按完整外部参考检验。用户要求盲测时，自审阶段只用允许的输入，锁定后才能揭示目标。

收益成立才采用；恶化或无明显收益时允许回退。首版已经有充分证据、重要关系成立且未发现关键缺陷时，可以说明保留依据，不强制为了轮数修改。观察到关键问题时，书面复审不能替代实际修订。

## 停止决定

复审后明确下一步，并在原有审片记录中保存依据：

- **继续修订**：已知关键缺陷仍妨碍当前目标，或重要检查可以完成但尚未执行。处理受影响部分，复查后再决定。
- **交付当前范围**：目标有对应的创作证据，关键问题已处理；说明保留的选择和停止依据。自评分、没有报错和已安装技能不能单独支持此决定。
- **带明确限制交付**：真实素材、感官证据或用户指定的制作范围存在限制。写明限制、依据及不能据此作出的质量结论；不自行发明时间预算或借“有局限”略过可完成的复审。

不以“每个维度都满分”或固定迭代次数定义完成。关键缺陷尚在时继续有目的的修订；候选没有带来收益时保留较好的版本并说明比较依据。只有真实缺失的输入或会改变已确认方向的选择才需要用户参与，内部检查不变成用户逐项审批。

## 用记录约束执行

本工作区使用 `creative-review.json` 承载上述决定，它是可编辑的审片记录，不另建与分镜冲突的时间表。需要防止导出后过早交付时，使用本技能的 `scripts/creative_review.py`：

```text
python <skill>/scripts/creative_review.py init --project <project> --record creative-review.json --artifact renders/film.mp4 --scope full --objective "原始观看目标" --target "本片最重要的质量目标"
python <skill>/scripts/creative_review.py check --project <project> --record creative-review.json
```

`init` 记录实际成片路径和哈希，状态为待复审；它不生成观看结论，也不覆盖已有记录。代理查看实际产物后填写观察、关键问题、必要候选和停止依据。`check` 校验路径、当前版本、证据类型、未处理的关键问题与决定：退出码 0 为记录允许当前范围交付，2 为需要继续处理，1 为命令错误。

记录中的字段按实际观察填写：

| 字段 | 内容 |
| --- | --- |
| `observations[]` | `at`、`finding`、`evidence`；证据含 `kind`（`visual` / `auditory` / `user_feedback` / `technical`）、项目内 `file` 与具体 `description` |
| `issues[]` | `at`、`problem`、`impact`（`major` / `minor`）、`status`（`open` / `resolved` / `out_of_scope`）；已处理或范围外项附 `resolution` 和 `evidence`。关键问题改为范围外须有对应用户范围说明 |
| `iterations[]` | `hypothesis`、`baseline` / `candidate`（各含 `file` 与 `sha256`）、`outcome`（`adopt` / `revert` / `pending`）、`reason` 和对照 `evidence` |
| `decision` | `action`（`continue` / `deliver` / `deliver_with_limits`）、`rationale`；带限制交付的 `limits[]` 含 `description`、`basis` 和 `evidence` |

没有发现的问题和未制作的候选使用空数组，不编造改动来填满结构。带限制交付表示准确交付已完成范围，不意味着未验证的创作目标也通过。

重新导出改变成片哈希后，旧复审不能直接当作新版本通过；回看受影响部分后更新记录。只重新导出相同内容时可复用对应证据。检查失败由代理继续处理，不交给用户审批。输出为带限制交付时，最终报告也要保留这些限制。

校验器只核对记录与文件的对应关系，不理解画面、验证反馈真实性或证明审美合格。禁止为取得通过而虚构观察、降低目标或将技术证据改标成观看证据。即使结构检查通过，已知实际缺陷仍按上面的修订原则处理。
