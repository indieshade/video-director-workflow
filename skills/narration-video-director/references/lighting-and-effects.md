# 光影、背景与特效

用于新作品的质感设计，或光影、背景、特效与主体缺少联系的修订。新作品默认先用 HyperFrames；方法也适用于现有 Remotion 项目。实现支持和 API 按当前项目版本核验，不把一次样片的效果写成所有题材的固定套餐。

## 从画面关系选择效果

先确定当前镜头应该让观众感受到的空间、材料、力量或变化，再选择实现。

按 [从观看感受推导设计](aesthetic-reasoning.md) 比较光与暗、清晰与柔化、密集与稀疏、持续与短促如何共同形成感受。局部效果的形状、面积、边缘和时间关系与主体一起设计；写实、平面和象征性处理各有用途，不把有光源、受光、Bloom 和粒子当作统一套餐。

沿用风格说明与分镜，为重要选择写清：

`表达用途 → 光源/效果起因 → 作用对象与空间范围 → 到达与衰减 → 实现与应看的帧/片段`

只有“高级光效、电影感、加 Bloom”不足以指导制作。比如夜幕落下，先减弱日光、改变环境明暗，保留主体轮廓；火出现时，再让邻近表面与背景响应其暖光。平面作品也可以通过块面、遮罩与局部明暗完成，不强制物理真实。既定的平涂、纸张或图表方向保留其材料语言。

## 光源与材料

- 确定重要光源的位置、方向、颜色、面积和作用；受光面、高光、投影与光源应有可读的关系。主光塑形，补光按需保留暗部，轮廓光服务分离，不能只把所有表面调亮。
- 接触阴影交代物体落在哪里；影子的方向、软硬、距离变化配合主体的位置。没有接触关系时，新增光晕不能修复漂浮感。
- 光影应体现材料：陶釉、粗糙木头、金属、纸张或发光体对光的响应不同。先检查粗糙度、反射和高光形状，再增加纹理；不用统一滤镜把所有材料抹成一种表面。
- 场景内的太阳、月亮、屏幕、火或能量体需要明确是否承担光源。承担时，设计附近受光对象、方向和影响范围；不承担时，保留其符号或平涂用途，不虚构物理灯光。
- 动态光源与动作共用时间锚点。光的出现、峰值和消退与起因匹配，可以有服务表达的延迟。光若只是辅助处理，检查它是否掩盖主体动作；光本身承担主要事件时，检查它的变化与结果是否可辨，不用关闭后事件仍存在作为通则。

## 背景参与构图与故事

背景先服务轮廓、注意力与情境。选择适合主体的明度、色温、负空间与空间层级；按需要安排前景遮挡、中景主体、远景环境。纯色、平涂或静止背景可以成立，不能为“有机”而让所有层持续移动。

有昼夜、情绪或能量变化时，背景、光源和主体受光沿同一故事状态变化，各层可以有不同的速度和幅度。避免只有背景换色、主体仍保持同样照明，或粒子与内容无关地循环飘动。空气透视、雾或景深用于建立距离；需要观看的动作、知识文本、字幕与证据保留可辨认性。

镜头移动时核对背景与主体的空间关系；需要真正深度时用真实 3D 或明确的分层视差。背景细节与运动强度服从当前主动作，不与主体争夺同一时刻的注意力。

## 特效与动作的配合

| 表达需要 | 可选择的处理 | 实际观察重点 |
| --- | --- | --- |
| 发光源或短促能量到达 | 局部辉光、受光变化、光晕 | 亮部保留形状，附近表面响应，暗部层次未被冲掉 |
| 力量、冲击、火势或材料变化 | 火花、烟尘、碎屑、扰动 | 有明确起因、发射位置和方向；峰值后消退，遮挡与尺度成立 |
| 快速位移或转动 | 子帧曝光采样或有意设计的拖影 | 速度与曝光相符；落定清晰；拖影不冒充真实曝光模糊 |
| 空间距离与观看焦点 | 分层对比、空气透视、按需景深 | 主动作可辨，焦点变化有用途，不整体柔化画面 |
| 内容转折与连续交接 | 遮挡、光变化、按需 shader 转场 | 注意力有交接；不让全屏效果掩盖尚未讲清的关系 |
| 材料与最终色彩统一 | 细微纹理、调色、按需颗粒 | 纹理尺度正确，细线/渐变在实际编码后仍成立 |

从最能改变当前镜头观感的处理开始。增添更多效果前检查其独立收益，避免同一时刻多种效果争夺焦点；强度、面积和时长按画面判断，不套固定数值。效果不必都模拟现实，但要能读出本片选择的形式关系。需要自然力量时检查接触、传递与衰减，需要图形表现时检查面积、方向、密度和节奏。主体轮廓、关键姿态或构图未成立时先修这些设计。

## 按框架接入成熟能力

- **2D**：SVG/Canvas 的路径、遮罩、渐变与局部滤镜配合 GSAP 时间线。保留清晰主体层和效果层，控制透明叠加与绘制范围；DOM、Canvas 和 WebGL 的滤镜不默认互换。
- **3D**：Three.js 光源和材质负责受光与体积；需要后期时优先核验现有 Three.js addons 或兼容库。按选择组织 EffectComposer/pass，检查 OutputPass、色彩空间与色调映射，避免重复处理导致亮度或颜色错误。更复杂的材质不自动更好，按可见收益与渲染成本选择。
- **HyperFrames**：读取匹配版本的 HyperFrames、GSAP 和所需 CLI 指导。由框架定位主时间线；相机、光强、效果强度、shader 时间和粒子状态接收同一视频时间。后期链路应在该次定位完成后实际绘制，不另建实时 RAF/ticker。
- **Remotion**：已有项目沿用其帧驱动集成与官方等待机制，需要 motion-blur、effects 或 R3F 后期时再读取对应指导。不把 React 专用组件和历史样片适配代码直接搬进 HyperFrames。

带内部时间或历史缓冲的 pass、粒子模拟、噪声与曝光采样需要额外检查。固定 seed；直接按视频时间求值，或使用可重复的预计算/烘焙状态，不能依赖此前是否播放过。多帧曝光使用实际子帧姿态；整数帧副本叠加和普通高斯柔化不能证明曝光效果。使用依赖时保留版本和素材就绪信号，第一次直接定位就应呈现主体与选定效果。

## 以实际输出回查

沿用制作规划的证据闭环，在接近最终的关键状态检查主次、轮廓、高光、暗部和材质；对动态效果检查起因前、峰值、中间变化及消退后的动作样段。用目标观看尺寸和实际导出检查，不能只看参数或未编码的开发预览。

效果影响难以判断时，对同一镜头开关或调整该效果，保持造型、时间、镜头和其他设计一致。关掉 Bloom 或模糊后更清楚，不等于该类效果永远不用；判断这次的对象、范围与强度是否合适。实际比较中改变了其他条件时说明变化，不把设计重做当作效果的单变量测试。

发现主体洗白、投影失联、暗部丢失、字幕被烟雾遮住、光效没有受光对象或首次定位缺失时，修具体关系并复查对应输出。技术检查通过只证明运行；静帧观察、连续观看、外部比较和用户反馈分别记录。不能宣称写进 skill 就已经追上外部作品。

## 官方能力来源

- [HyperFrames 运行时、3D 与转场](https://github.com/heygen-com/hyperframes/blob/main/docs/prompting/runtimes-and-3d.mdx)：按视频时间适配运行时，真实深度、光照与相机按需用 Three.js。
- [GSAP 缓动](https://gsap.com/docs/v3/Eases/)：速度曲线属于编排工具，光效的起因、时序与观看用途由本片设计。
- [Three.js 后期](https://threejs.org/manual/pages/post-processing.html)、[UnrealBloomPass](https://threejs.org/docs/pages/UnrealBloomPass.html)：复用成熟后期，核验绘制顺序及输出色彩。
- [MeshPhysicalMaterial](https://threejs.org/docs/pages/MeshPhysicalMaterial.html)：高级材料属性和成本按实际需要选择；环境反射与照明共同决定表现。

以上来源说明实现能力；设计取舍与检查方法是本技能的制作指导，不是对 Opus 内部实现的推断。
