# 线条与 SVG 设计

用于解说视频中的关系线、图形主体、标注、图表和剪贴辅助图形，以及这类元素的局部修订。目标是让图形解释内容，并与同一画面的素材、字体和动作形成有意的关系。SVG 是表达媒介，不代表某种审美；Rough.js、滤镜和真实照片都不能单独证明设计成立。

## 先决定画什么，再决定怎么画

区分对象本身、观察或说明它的图形。太阳是叙事主体时，考虑其轮廓、结构与光感；太阳只是光源符号时，抽象圆形也可以成立。照片旁边的图形可以保持清晰简洁，不必给两者施加同一种纹理，但需要明确它们分别承担主体、证据还是注释。

内容复杂且材质关键的主体，评估照片、栅格插画或 3D；需要明确结构、精确关系、连续变形或风格化形象时，评估 SVG。选择 SVG 时，设计有辨识度的轮廓、块面和内部结构，避免仅用圆、矩形和通用图标拼凑所有题材。

复杂轮廓可使用现成可编辑向量、矢量编辑器或定制路径，不以“能快速写出 JSX”作为素材选择标准。现有角色或图形系统优先延续其比例、边缘和细节尺度。

## 标准图形优先复用

箭头、连接线、流程图节点、括号和常用符号，先检查项目已有组件、成熟库或可编辑矢量素材；不要默认逐镜头手拼路径和几何零件。按 [工具复用与依赖选择](tool-selection.md) 核对能力后，把代码用于本片的构图、语义端点和风格适配。调用绘图 API 画了线，不等于已经复用了箭头组件。

例如，`perfect-arrows` 可提供中心曲线和方向信息，最终绘制仍需接入当前框架；需要实心剪纸箭头时，可用 Clipper 等成熟几何库完成线宽扩展与轮廓合并。它们是可选实现，不要求所有项目安装同一套库，也不把所有箭头统一为剪纸风格。

## 按语义分配笔触

从当前场景实际需要的角色中选择，不要求每幅画都有以下所有线条。

| 角色 | 设计判断 | 常见失效 |
| --- | --- | --- |
| 主体轮廓与结构 | 用轮廓识别对象；可依靠块面而省去外描边，内部结构从属于主体 | 所有物体都包同样粗的轮廓，细节像图标拼接 |
| 力、光线、流向 | 保留真实方向和几何关系；决定是否需要箭头，以及头部与线身的比例 | 重复的大箭头比被解释的对象更抢眼，随意弯曲平行光线 |
| 轨迹与范围 | 分清真实运动路径、可选位置、边界或视觉引导；虚线应有可解释的含义 | 用同一种虚线表示轨道、视线、未完成和装饰 |
| 标注引线 | 端点明确落在对应对象或局部；避开关键表面和文字 | 穿过主体，或与流向线混淆而制造错误因果 |
| 数据、坐标与测量 | 优先精确位置、端点和刻度；材质处理不能改变读数 | 为了手绘风格扭曲数据，或弱化到目标尺寸下看不见 |
| 强调与观察标记 | 将较高对比或特殊笔触留给当前理解的关键 | 全部线条使用强调色和同样的运动，失去注意力层级 |

线条不是越细、越淡越好。主动作、科学关系或观察标记需要足够可见；辅助线可以降低层级。先看目标显示尺寸和背景明暗，再调线宽、对比、数量及间距，不套固定像素值或通用透明度。

## 建立场景使用的图形规范

沿用作品的 `style.md` 或等价文件，补齐当前缺失的选择即可：

- **层级**：哪类线是主线、辅助线、强调线；它们的宽度和对比如何区分。
- **形态**：端点、转角、箭头头部、虚线节距、轮廓是否封闭；同角色保持一致，不强求不同角色同形。
- **材质**：干净技术图、印刷笔触、手绘草图或有体积的插画，依据主题与参考选择。
- **色彩**：区分对象自身颜色、注释颜色和强调颜色；不把所有关系线染成品牌强调色。
- **层次**：图形相对主体的位置、遮挡与留白；连线不要无意覆盖证据或对象细节。
- **动作**：画线、对象带动线条、端点移动或保持静止，选择符合语义的方式。

这些选择应能够指导同类元素的绘制。不要只写“高级、有质感、Vox 风格”。在代码中复用按语义命名的样式或组件，避免每条路径随手设不同参数；已有组件成立时继续使用，不为小修搭新的绘图框架。

## 先解决形状、层级与路线，再加材质

**路径与轮廓**：减少无意义的控制点，保持预期的切线、转折和轮廓重心。硬转角或不规则边缘也可以是有意选择。箭头与曲线末端方向一致；主线和相邻标注留有间距。可用有宽度变化的闭合路径表达笔锋或渐细的光束，而不只改变整条路径的 strokeWidth。

对需要优雅弧线的连接或隐喻，先设计无笔触的中心线：指定有语义的端点、转折和避让区域，再用少量曲段连接。连续贝塞尔段的接头检查切线方向与曲率变化；故意折角另行说明。绘图库负责采样和插值，不能自行决定路线。不要把数学振荡、多次随机扰动或密集采样点当作图形设计。

箭头位置与朝向从同一路径的终点和切线求值，避免另画一个目测对齐的头部。粗实心或剪纸箭头优先生成连续闭合轮廓，统一填色与材质裁切，避免接缝、重复覆盖和纹理溢出。SVG marker 也是规范实现：与路径端点绑定，并随切线自动定向；不是所有箭头都必须合为一个 path。绘制过程中头身仍需相连，不能让固定方向的独立三角头突然出现。先在常用观看尺寸检查完整路线，再检查绘制过程的注意力；渐显不会使一个杂乱轮廓变得清楚。

情绪性线团也需要可读的轮廓与节奏。根据情绪决定交叉、留白和张力，避免用反复叠加同等粗细的线表示“复杂”。笔锋变化服务转折与重点；先减少无意交叉和相近轮廓，再考虑perfect-freehand、Rough.js或纹理。干净关系线与有压力的强调笔触可以并存，不要求全场手绘。

**空间与遮挡**：区分图形在对象后面、贴在对象表面还是位于注释层。连接端点和路径在移动期间也应保持关系成立。用分层、裁切或蒙版解决遮挡，避免仅把穿越主体的线条变淡。

**印刷材质**：需要时增加细微墨迹覆盖变化或边缘不规则，并在同类图形中保持尺度一致。先做无纹理版本，确认问题是否已经由几何和层级解决。颗粒不能切断必要的细线，规则网点不自动适合任何主体。

**手绘材质**：用 Rough.js 或定制路径控制笔锋与轮廓，保持随机种子稳定。粗糙程度、复线和排线取决于视觉方向；测量线、刻度和准确关系可以保持规整。不要用全局随机抖动模拟画工，也不要把所有对象画成同一种草图。

**光感与体积**：渐变、柔边和亮暗需要对应光源、材质或叠层。说明光束可以简化，不应为了“丰富”随意增加辉光和阴影。不同图形可以有不同材质，前提是视觉角色明确、层级协调。

## SVG 实现中会破坏设计的细节

- 使用明确的 viewBox、坐标与缩放策略。标注应保持视觉线宽时，可评估 [vector-effect="non-scaling-stroke"](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Attribute/vector-effect)；对象轮廓需要随对象缩放时，保留随缩放变化的线宽。不把该属性用于所有路径。
- 将 [stroke-linecap](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Attribute/stroke-linecap) 与转角样式纳入规范；圆端、平端、硬角各有用途。短虚线加圆端后更接近点状，检查是否仍表达原意。
- 定义可识别且不冲突的 defs ID，并把相关滤镜、marker 和蒙版与组件作用域一起管理。复用同一组件或同屏多个 SVG 时，检查引用是否仍指向正确资源。
- 核查 [filterUnits](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Attribute/filterUnits) 和过滤区域。细长、纯水平或垂直路径尤其需要检查；必要时使用 userSpaceOnUse 并明确留边，不让滤镜区域裁掉端点或笔触。蒙版边缘需要计入实际线宽。
- 在最终画幅、常用观看尺寸及编码后检查：细线是否丢失，密集虚线是否闪烁，颗粒是否变成噪点。固定材质种子，避免每帧生成新噪声；动效依然由 Remotion 帧控制。
- 不默认给每条路径叠加滤镜。出现渲染负担或压缩噪声时，减少处理范围或改用预制素材；不能通过改成占位图形来宣称问题解决。

## 审阅与修订

局部修订选取能暴露问题的实际帧，先问：这条线说明什么，删去后是否影响理解？保留必要线条，再检查层级、路径、端点、材质与对象的关系。需要探索时，比较一个能隔离问题的差异，例如“相同几何的两种笔触”或“原路线与避让主体的路线”；已有清楚方案不强制生成多版。

静帧检查材质与构图，连续片段检查移动时的遮挡、箭头朝向、笔触稳定和注意力交接。导出检查细线和纹理在缩放、压缩后是否仍成立。复查应围绕本次问题，不按工具使用数量打分。

箭头修订挑选片中有代表性的短线、转向或反向路径，以及绘制中的状态，核对头身连接、方向、比例与语义端点。放回实际背景后再看可见性：深色箭头融入深底也会看起来像断开，须调整对比或层次；独立白底样张和几何连通性检查不能代替实片检查。

### 月相样片的反例

初版使用真实月面纹理，却把太阳做成带规则网点的平涂圆，五条粗橙色箭头及多组等节距虚线抢占注意力。用户指出太阳与线条质感差。问题不只在缺少纹理，也在主体的表达、注释层级和材质分工未统一。

v2 换成太阳观测素材、减少光线、细化笔触和加入微颗粒；这是一次修订尝试，尚未得到用户对整体线条设计的确认。不要将 v2 的“更细、更淡、带颗粒”推广为通用解法。下一轮需要实际看关系是否更清楚、必要线条是否过淡，以及观察标记是否仍承担焦点。

从此例迁移的是判断方式：主体是否需要真实材质，辅助图形是否抢戏，线条的语义和层级是否清楚。对纯矢量插画、漫画或技术图，应采用各自成立的规范。
